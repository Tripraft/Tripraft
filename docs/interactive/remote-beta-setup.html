One origin and one application database

The prepared Docker deployment serves the React website and Flask API from the same public URL. Login cookies and CSRF tokens stay on that origin. The two laptops use the beta website to collaborate.

India and USA browsers→Render website + API→Supabase PostgreSQL

Redis connects to the API. Gmail API delivers existing email templates over HTTPS. Travel reference catalogs are bundled separately; they are not the application database.

Opening localhost still opens your own laptop. Send the new public beta invitation link to your friend.

Deploy the shared beta
  1. Restore GitHub CLI access if necessary: gh auth login -h github.com --git-protocol https. Review and commit these setup files, then publish the reviewed work to develop. Keep personal runtime databases out of the commit.
  2. Create an empty Supabase beta project and Upstash Redis database. Choose service regions deliberately. Copy the exact session-pooler and TLS Redis URLs.
  3. In Google Cloud, enable Gmail API and obtain your sender OAuth client ID, client secret and offline refresh token. Set FROM_EMAIL to that same Gmail address. Follow the Gmail setup instructions. External Testing OAuth grants expire after seven days; plan publishing status and reauthorization before unattended use.
  4. Render → New → Blueprint → your private Tripraft repo. Select branch develop and Blueprint path infra/remote-beta/render.yaml. The configuration explicitly selects the Free plan.
  5. Fill in the variables requested by Render. Use your assigned Render HTTPS URL for both FRONTEND_URL and CORS_ORIGINS. If its final URL differs, update both and redeploy.
  6. The image builds the frontend with VITE_API_BASE_URL=/api. Startup validates configuration, validates the canonical catalog, applies Alembic migrations to the configured beta database, then starts one Gunicorn worker.
  7. Check build/start logs, PostgreSQL connection, Redis connection and the public health endpoint. Use new staging accounts and verify email delivery before inviting your friend.
Do not set TRAVEL_DATA_URL to the Supabase application database. The image includes the repository's two SQLite reference catalogs. A catalog's presence does not guarantee that it contains all destinations.

      
Open Sapling Interactive Smartlog
Sapling SCM is already installed on this laptop. The helper uses sl.exe explicitly to avoid PowerShell's sl alias. It opens the local repository on port 8081.
powershell -ExecutionPolicy Bypass -File infra\tools\open-smartlog.ps1
Or run the executable directly:
& "C:\Program Files\Sapling\sl.exe" web --port 8081 --no-app
In Smartlog, select a commit to see its author, time, files and diffs. The tool's generated local URL contains an access token; do not publish that URL. Each developer runs Smartlog on their own laptop.
git fetch origin --tags
git log --oneline --graph --all --decorate -15
Fetch updates repository history. It does not copy uncommitted changes from another laptop. Use feature branches and PRs into develop, with a release tag only after acceptance checks pass.

Scope and limits
Remote testing is still pending credentials and deployment. The hosted Docker image cannot be built on this laptop until Docker is available. Local tests and a web build check the implementation; Render logs are the next deployment check.
Render Free can sleep, has resource limits and ephemeral storage, and blocks common SMTP ports. The Gmail HTTPS adapter avoids the SMTP dependency. A Gmail password or app password cannot replace the OAuth grant. For persistent uploaded images and vault files, configure durable storage or a paid disk before depending on uploads across restarts. The Free Blueprint does not provision a paid disk.
The staff console and optional workers are not hosted by this beta service. Periodic jobs, AI integrations, complete travel data and partner file persistence require separate acceptance checks. No existing local accounts or invitations are migrated automatically.
Do not expose the mutating Smartlog interface publicly. Invite teammates through GitHub. Back up PostgreSQL before future schema upgrades; restoring a code tag does not restore database contents.
