How these requests relate to the app

Opening personal expenses reads the session, currency preference, expense and income pages; expense/income pagination runs in parallel. Returning to a loaded tab reuses cached ledger data. Switching to group cards and opening a group are separate reads. Extra ledger pages add requests. Currency changes save a preference and may need one rate lookup per source currency; loaded browser-session rates are reused. Saving a group preference updates the UI from the committed response, then reconciles data in the background.

What can still be improved

Measure real browser navigation and production PostgreSQL first. Group expense edits still use 34 SQL statements in this small fixture; eager-loading and batching are the next query-reduction candidates. Large ledgers still need all pages for complete analytics. Cold FX calls and email transport remain external dependencies. Live focus/reconnect reconciliation owns refreshes, avoiding duplicate group-query focus reads.
